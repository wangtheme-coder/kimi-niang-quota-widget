# Kimi 娘额度挂件

一个使用 Kimi Code 当前登录状态的只读额度插件与桌面看板娘。上方显示 5 小时窗口已用量，下方显示 30 天月度总额度已用量；进度条越满，使用越多。

![挂件预览](docs/preview.png)

> 预览图使用真实额度接口渲染，数值已随账号变化，仅示意界面。

## 已实现

- 真实额度查询，60 秒自动刷新与手动刷新；睡眠恢复、解锁、宿主恢复可用及网络恢复时立即补刷新
- 5 小时、30 天已用百分比及各自重置倒计时
- 单击角色展开/收起，默认 10 秒自动收起，也可改为 5 秒、30 秒或关闭
- 输入框左下方、底部空白状态栏的 30×30 圆形头像入口，单击呼出角色与额度面板；连续点击或重复启动不会多开
- 只在标题为 `Kimi Code` 或 `Kimi` 的客户端主窗口内活动；订阅网站等内部弹窗不会成为宿主，不全局置顶、不越出宿主边框
- 按压回弹，拖动后吸附宿主左右边缘并切换角色朝向，宿主移动/缩放时跟随
- 最后一个 Kimi Code / Kimi 客户端进程退出后，挂件自动退出；最小化不会触发退出
- 角色与额度面板分别调整 80%–150% 大小，设置立即保存；宿主空间不足时自动等比适配
- 可选小黄鸭或短促电子按压/松开音效，以及 Kimi Code / Kimi Work 完整后台任务完成音效，独立开关、音量与试听；普通分段回复不播放完成音
- 查询失败时保留上次成功快照，并明确标记错误
- 演示模式使用明确标注的模拟数据，不冒充真实额度
- Kimi 插件清单、MCP 查询工具、会话启动及任务完成 hooks

## 桌面运行

需要 Windows、Node.js 20 或更新版本，以及已登录的 Kimi Code。

```sh
npm ci
npm start
```

界面演示（不读取账号，不发起额度请求）：

```sh
npm run demo
```

操作：

- 单击角色：展开或收起额度气泡；展开一段时间后会自动收起，面板内操作重新计时。收起后面板真正隐藏，其原区域鼠标穿透，可直接点击下面的宿主内容。
- 单击输入框左下方、底部空白状态栏的圆形 Kimi 娘头像：呼出角色并展开额度面板；连续点击不会多开。
- 拖动圆形入口：移动到宿主内任意位置，松手不吸附、不触发额度面板；位置在重启后恢复，窗口缩放时按相对位置跟随。
- 拖动角色或透明区域：在宿主窗口内移动，松开后吸附到宿主较近的一侧。
- 右键 → `挂件设置`：选择自动 / Kimi Code / Kimi 客户端宿主，分别调整角色和面板大小、自动收起时间、音效开关及音量，并可试听。
- 右键菜单还可刷新、切换宿主边缘吸附/演示模式；`退出 Kimi 娘（保留快速入口）`只关闭角色和额度面板，不结束挂件进程，单击圆形入口即可重新打开。
- `Esc`：收起气泡；`F5`：刷新。

角色图片位于 `assets/kimi-niang.png`。文件缺失时使用临时占位角色。设置窗口属于桌面挂件；Kimi Code 插件管理器目前不提供插件自定义原生设置页。

## 宿主窗口行为

挂件是宿主的 Windows 附属窗口，不向 Kimi 进程注入代码，也不作为全局置顶图层。圆形快速入口同样属于附属窗口，并非注入客户端原生输入栏的按钮。跟踪器只接受标题严格等于 `Kimi Code` 或 `Kimi` 的可见顶层窗口，不使用会被内部弹窗取代的 `MainWindowHandle`。自动模式优先选择前台的客户端主窗口；当前宿主最小化时转去另一个未最小化的宿主，两个都最小化才隐藏，恢复任意一个后会自动上线。订阅网站、设置页等内部弹窗即使成为前台窗口，也不会成为挂件宿主。其它应用前台时，挂件仍只在宿主区域内，并遵守 Windows 的普通窗口层级。

角色位置按宿主相对偏移保存，入口位置按宿主可用区域的比例保存，因此重启、宿主移动或缩放后仍在原位置附近。入口默认位于输入框左下方；独立附属窗口无法读取客户端内部的侧边栏展开事件，手动展开或收起侧边栏后可直接拖动入口调整位置。宿主被缩小到容纳不下挂件时，角色与面板会临时等比缩小；恢复宿主大小后回到用户设置的比例。边界钳制包含透明窗口取整的安全内边距。所有 Kimi Code / Kimi 进程持续消失 1.5 秒后挂件自动退出，短暂窗口重建和最小化不会误退；即使设置“仅 Kimi Code”，也会把仍运行的 Kimi 客户端计入宿主存活状态。该功能依赖 Windows 窗口接口，不支持 macOS / Linux。Kimi Work / Kimi Chat 若在 `Kimi` 客户端窗口中运行，可以作为视觉宿主，但这不代表插件获得了其任务数据。

## 作为第三方 Kimi Code 插件安装

这是可由用户自行分发的第三方插件，不是 Kimi 官方插件，也不是 DSH bundle。发布到 GitHub 后，在 Kimi Code 中执行：

```text
/plugins install https://github.com/wangtheme-coder/kimi-niang-quota-widget
/reload
```

也可以把 Release 的 ZIP URL 交给 `/plugins install`。插件管理器的 **Custom** 页支持从 URL 安装；本仓库的 `marketplace.json` 还可作为个人自定义市场目录：

```text
/plugins marketplace https://raw.githubusercontent.com/wangtheme-coder/kimi-niang-quota-widget/main/marketplace.json
```

自定义市场不等于进入官方 Curated 合作伙伴列表。安装或更新后执行 `/reload` 或 `/new`，当前会话不会自动应用插件变化。

本地开发时可直接安装源码目录：

```text
/plugins install C:\Kimi
/reload
```

插件会被复制到 `$KIMI_CODE_HOME/plugins/managed/kimi-niang-quota/`。首次会话启动或调用 `open_widget` 时，插件会根据 `package-lock.json` 自动准备 Electron 桌面组件，完成后自动打开挂件，无需再进入托管目录手动安装。首次准备需要网络和 Node.js 20 或更新版本；安装日志位于 Electron 用户数据目录的 `runtime-install.log`。`get_quota` 不依赖 Electron，即使桌面组件尚未准备好也能查询。

同一份插件文件也发布到 npm，方便镜像、离线或内部分发：

```sh
npm pack kimi-niang-quota-widget   # 拿到与 Release ZIP 内容一致的文件
```

npm 包不携带 `package-lock.json`（npm 发布时会剔除），首次准备桌面组件时会自动退回 `npm install`；Release ZIP 里带 lockfile，走 `npm ci`。

插件提供：

- `get_quota`：只读查询当前账号，不创建聊天或模型请求。
- `open_widget`：启动或呼出桌面挂件，首次使用自动准备桌面组件。
- `/kimi-niang-quota:quota`：通过 Agent 查询并解释额度。
- `SessionStart` hook：启动桌面挂件，缺少运行组件时自动准备。
- `Notification` + `task.completed` hook：仅在完整后台任务完成时播放完成音；普通 `Stop` 分段回复不触发。

从源码构建标准第三方插件 ZIP：

```sh
npm run check
npm run package
```

产物位于 `dist/kimi-niang-quota-widget-v<版本>.zip`，清单位于 ZIP 根目录，不包含 `node_modules`、本机设置、额度缓存或调试产物。

## 作为 Kimi Work 个人插件导入

发布 GitHub 后，在最新版 Kimi Work 中唤起 **Plugin Builder**，把仓库链接交给它导入；然后进入「插件」→「个人」安装，并在新会话中测试。桌面组件同样由启动脚本在首次使用时自动准备。

Work 的实际 Plugin Builder 转换和安装需要在客户端中确认；源码包内的模拟 Work hook 已验证能通过同一通知桥播放完成音，但不代替客户端端到端验收。

## 音效与客户端边界

按压音效组可在设置中选择 **小黄鸭（默认）** 或 **短促电子音**，选择立即保存并共用按压音量。点击音效输出增益为 `2.5`，设置 100% 时对应初版输出的 2.5 倍；完成提示音不应用该增益。小黄鸭按下音高略低、松开略高；完成提示为三音和弦。所有音效均由 Web Audio 实时合成，不使用 DSH 的音频素材。Hooks 通过 Windows 本机命名管道通知已运行的挂件；挂件未运行时安静退出，不会仅为播放声音而弹出窗口。短时间内的重复完成事件会去重。

完成事件接入 **Kimi Code 与 Kimi Work** 的官方 Hooks。Kimi Chat 尚无已验证的任务完成 Hook 或进度 API，因此暂未接入任务音效和进度查询；插件不会读取客户端私有聊天数据。Chat 与 Work 都能使用 `Kimi` 窗口作为视觉宿主，但视觉宿主与任务数据接入是两件独立的事。

## 数据与隐私

额度来自 `https://api.kimi.com/coding/v1/usages`。30 天栏采用 `usages.limit_month_total`，不是 `limit_month_code`。令牌只在本机内存中读取，并仅用于该 Kimi 请求；不会写入设置、缓存、日志或发送到第三方。

设置和不含凭据的额度快照保存在 Electron 的用户数据目录。完成 hook 只向本机挂件传递事件类型、来源和会话标题，不读取或传输令牌及聊天内容。宿主跟踪只在本机使用进程名、顶层窗口标题、窗口句柄、矩形和最小化状态；窗口标题仅用于严格匹配 `Kimi Code` / `Kimi` 主窗口，不保存、不输出，也不读取会话内容。该 usages 接口没有第三方稳定性承诺，未来字段变化可能需要更新解析器；查询失败不会用本地 Token 统计或随机值替代真实额度。

## 验证状态

```sh
npm ci   # 按 package-lock.json 安装
npm run check   # 全部 JS 语法检查
npm run package   # 构建标准第三方插件 ZIP
```

2026-10-27 在 Windows 11 + Node.js 22 + Electron 39.8.10 实机验证通过：

- `npm ci`、`npm run check`、`npm start`（演示模式与真实账号）均可启动，渲染进程无控制台报错。
- 真实接口返回 `limit_5h` / `limit_month_total` / `limit_month_code` 三个键，30 天栏取自 `limit_month_total`（实测 5.96%），不是 `limit_month_code`（实测 5.93%）。
- 5 小时与 30 天两条进度条、已用百分比、剩余量与重置倒计时显示正常，未出现裁切或重叠。
- 挂件是 Kimi Code 主窗口的 **附属窗口**（owner 为宿主 HWND），未设置 `WS_EX_TOPMOST`，位置被钳制在宿主矩形内。
- 本机命名管道 `\\.\pipe\kimi-niang-quota` 可连接，`scripts/notify-widget.cjs` 发送完成事件后安静退出（0）。
- 同时打开 Kimi 客户端与 Kimi Code 时实测：前台切换宿主、任一宿主最小化时自动切到另一个、两个都最小化时隐藏、恢复后自动上线（20 项自动化验收全过）。
- 单击展开/自动收起、右键展开、拖动换边并吸附、角色与面板独立缩放、按压与完成音效均实测通过。

v0.3.0 补齐第三方插件元数据、自定义市场目录、标准 ZIP 打包和首次桌面依赖自动准备。在 Windows 11 + Node.js 24.21.0 实测：发布包不含 `node_modules` 时 `npm run check` 与真实 `get_quota` 均通过；首次自动安装 70 个 npm 包用时约 7 秒；没有旧挂件实例时启动脚本能实际拉起 Electron，重复启动后主实例仍为 1 个；独立配置目录下演示界面可运行。ZIP 使用标准 `/` 路径且清单位于根目录。GitHub 发布后的仓库 / Release URL 安装需在实际上传后验收。

`npm run package` 现在用自带的 ZIP 写入器打包：条目按路径排序、时间戳固定、路径分隔符统一为 `/`，同一份源码重复打包得到的 SHA256 完全一致，便于校验发布件。

v0.3.7 完成提示音只响应 `Notification(task.completed)`，移除每轮回复结束都会触发的 `Stop` Hook，并在通知脚本内拒绝非 Notification 事件。已用真实 Hook 脚本验证普通分段回复静默、完整后台任务完成发送一次事件。

v0.3.6 移除角色按钮的原生 `title` 悬停提示，修复宿主切到后台后提示仍残留屏幕、只有重新打开宿主才消失的问题；保留无障碍标签，不改变角色交互和用户设置。

v0.3.5 在 v0.3.4 基础上将点击音效再放大 1.5 倍，总输出增益为 2.5；完成提示音和已有音量设置不变。已验证 Web Audio 增益比例和五种音效实际调用。

v0.3.4 将小黄鸭与短促电子点击音效的输出增益调整为 `1 / 0.6`，100% 设置的响度约为旧版的 1.667 倍；完成提示音不变，已有音量设置不变。已验证 Web Audio 增益比例和五种音效实际调用。

v0.3.3 补齐睡眠恢复、解锁屏幕、宿主恢复可用和网络恢复后的立即刷新；60 秒定时刷新保留。隔天旧快照增加月日显示，悬停可查看完整成功快照时间。已用真实额度接口验证网络恢复刷新和完整定时周期刷新；系统睡眠事件已接入 Electron `powerMonitor`，未伪称完成整夜睡眠实测。

v0.3.1 修复右键退出会把快速入口一起关闭的问题。现在退出只隐藏角色与设置窗口，圆形入口和挂件进程继续运行；宿主移动或恢复时不会擅自重新弹出角色，点击入口会重新显示角色并展开额度面板。已通过真实 Electron 右键菜单与入口点击的端到端验收。

v0.2.4 将入口移到输入框左下方的底部空白栏，透明窗口缩小为 36×36（可见头像仍为 30×30），并加入自由拖动与相对位置保存。真实鼠标验收通过：拖动 120×60 像素后入口跟随且不展开面板，普通单击正常展开；宿主缩小 200 像素后入口移动 62 像素，恢复原尺寸后回到原位；重启后位置恢复仅有 1 像素 DPI 取整误差。测试产生的拖动位置已清除，正式实例恢复默认位置并关闭临时调试端口。

v0.2.3 新增状态栏圆形入口与宿主退出联动。隔离实例实测：连续点击入口只展开面板、第二次启动只有一个主实例；入口与角色 owner 均为当前宿主，最小化时一起隐藏、恢复后一起上线；宿主移动跟随即有 1 像素以内的 DPI 取整误差。小黄鸭与短促电子音均实际调用成功，下拉选择已保存并在重启后恢复。模拟进程枚举确认“全部退出”计数为 0，而“仅 Code 无窗口但 Kimi 仍存活”计数为 1。另用两个真实窗口进程运行隔离副本完成端到端验收：第一个宿主退出后挂件转移至另一个并继续运行，最后一个宿主退出 1.5 秒后挂件主进程退出；整个测试未关闭用户的真实客户端。

v0.2.1 修复：宿主最小化时 Windows 会给出 `-25600,-25600` 的 `159x27` 占位矩形，旧版会把它当真实宿主尺寸，导致挂件被缩到约 6%（并可能停在错误的宿主上）。现在跟踪器与主进程都会忽略最小化宿主，自动模式也不会把"仍处于前台但已最小化"的窗口当作宿主。

**未验证**：Kimi Work 的 Plugin Builder 导入转换与「插件 → 个人」安装流程；Kimi Chat 的任务事件与进度接口（未接入，也没有对外宣称支持）。这些项目需要在对应客户端中人工验收。
